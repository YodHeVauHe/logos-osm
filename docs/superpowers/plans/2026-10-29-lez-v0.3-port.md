# LEZ v0.3.1 OSM Registry Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy and use LP-0018's OSM registry with the LEZ v0.3.1 plan/apply ABI.

**Architecture:** The guest emits shard effects for a public registry PDA under the deployed program account; apply validates and writes Borsh registry bytes. The CLI/SDK use v0.3.1 wallet and sequencer RPC interfaces for transactions and reads.

**Tech Stack:** Rust, `lee_core` from LEZ tag `v0.3.1`, RISC Zero 3.0.5, Borsh, LEZ wallet/RPC, Cargo.

**Spec:** `docs/superpowers/specs/2026-10-29-lez-v0.3-port-design.md`

## Global Constraints

- Pin every LEZ git reference to `tag = "v0.3.1"`.
- Keep `risc0-zkvm = 3.0.5` as selected by LEZ v0.3.1.
- Store the `Registry` in the public program owned shard at the `registry` public PDA, with a 100 KiB ceiling.
- Do not deploy to testnet, push, create repo wallets/keys, or alter prize text.
- Preserve SDK `RegistryClient` API and stable `E_*` codes when practical.
- Do not add or run tests unless user asks to test or verify. (The user explicitly asked for TDD and the full verification gates in this task.)

## Review Focus

- Wrong owner/program account selector: tests reject foreign registry shards and malformed account lists.
- Existing registry passed to init: test proves init is idempotent and preserves bytes.
- Malformed/oversized batch or state: tests assert stable deserialize/batch/full errors and no partial write.
- Timestamp ordering and duplicate regions in one batch: tests pin deterministic last-write behavior and ordering policy.
- Missing account shard in sequencer response: query returns `None`, while a present empty registry decodes as an empty map.
